# Custom providers

A custom provider is any server that speaks the OpenAI chat completions API or the Anthropic messages API. This includes local servers such as llama-server, LM Studio, Ollama, and vLLM, and hosted APIs that are compatible with one of the two.

To add one, open Settings › Providers and click **+ Add provider**. Set the name, the API format, and the base URL. An API key is optional: local servers usually need none. Add model ids if the server does not list its models. If the server's models think, check **Supports thinking** (see [Thinking](#thinking)).

You can also add custom providers by hand in `~/.config/dez/app_state.json`. **Close Dez first.** Dez saves this file while it runs, so it overwrites changes made while it is open.

```json
{
  "customProviders": [
    {
      "id": "ollama",
      "name": "Ollama",
      "baseUrl": "http://localhost:11434/v1",
      "models": [{ "id": "llama3.2", "name": "Llama 3.2" }]
    },
    {
      "id": "claude-proxy",
      "name": "Claude proxy",
      "baseUrl": "https://llm.example.com",
      "apiFormat": "anthropic",
      "apiKey": "sk-..."
    }
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | 1 to 64 letters, digits, `-`, or `_`. It must not be a built-in id (`venice`, `trustedrouter`, `openrouter`, `apimart`, `charm_hyper`, `zai`, `anthropic`, `minimax`, `kimi`, `copilot`), `__favorites__`, or a JavaScript `Object.prototype` name such as `__proto__` or `constructor`. |
| `name` | yes | The name in the model picker and in Settings. |
| `baseUrl` | yes | An `http://` or `https://` URL with no query (`?`), fragment (`#`), user name, or password. See the base URL rule below. |
| `apiFormat` | no | `openai` (default) or `anthropic`. |
| `models` | no | Models that always show, as `{ "id": "...", "name": "..." }`. The name is optional. Add `"imageInput": true` or `false` to tell Dez if the model reads images; it has priority over `modelImageInput`. Add `"audioInput"` and `"videoInput"` (`true` or `false`) to tell Dez if the model reads audio or video clips; they have priority over `modelAudioInput` and `modelVideoInput`. Add `"toolCalling": true` or `false` to tell Dez if the model calls tools; it has priority over `modelToolCalling`. Add `"thinking": true` or `false` to tell Dez if the model thinks; it has priority over `modelThinking`. Add `"outputs"` (a list of `text`, `image`, `audio`, `video`) and `"request"` (`chat`, `image`, `imageEdit`, `upscale`, `tts`, `music`, `video`, `imageToVideo`, `videoToVideo`, `voiceChange`, `transcription`, or `none`) to tell Dez what the model makes and how to send it a request; they have priority over `modelOutputs`. Add `"contextWindow"` (a number of tokens) to tell Dez the context window of the model; it has priority over `modelContextWindow`. Add `"fetchedOnly": true` when the entry only corrects a model that the server lists: Dez then shows the model only while the server's model list has it, in the server's order. Only such an entry can have `"outputs": []`, which hides the server's model of its id (for example, an embedding model that the server lists with its chat models). |
| `fetchModels` | no | `true` (default) also lists the models that the server reports. `false` never asks the server. |
| `modelListQuery` | no | Query parameters for the model list request, as `{ "name": "value" }`, e.g. `{ "type": "all" }`. |
| `modelImageInput` | no | Where the server's model list tells if a model reads images, as `{ "path": "..." }`: a dot path in each model entry, e.g. `architecture.input_modalities`. A `true` or `false` there is the answer; a list there means "reads images" when it holds `"image"`. Add `"missing": false` (or `true`) to give the answer for an entry with no value there. |
| `modelAudioInput`, `modelVideoInput` | no | Where the server's model list tells if a model reads audio clips or video clips, read as `modelImageInput` is; a list there means "reads audio" when it holds `"audio"`, and "reads video" when it holds `"video"`. Dez sends a clip only to a model for which the answer is `true`, and only when the provider has `chatClips`. |
| `modelToolCalling` | no | Where the server's model list tells if a model calls tools, as `{ "path": "..." }`, e.g. `supported_parameters`. A `true` or `false` there is the answer; a list there means "calls tools" when it holds `"tools"`. Add `"missing": false` (or `true`) to give the answer for an entry with no value there. Dez offers its tools to a model unless it knows that the model cannot call them. If the server refuses requests that offer tools (e.g. with HTTP 400), turn off the Tools toggle in the model picker's settings popup, or set `"toolCalling": false` on the model in `models`. |
| `modelThinking` | no | Where the server's model list tells if a model thinks, as `{ "path": "..." }`, read as `modelToolCalling` is; a list there means "thinks" when it holds `"reasoning"`. A model that is known not to think gets no Thinking toggle, and its requests get no `thinking` fields. |
| `modelOutputs` | no | Where the server's model list tells what a model makes, as `{ "path": "...", "values": { ... } }`: a dot path to a type, or a list of types, in each model entry. `values` gives each type its `outputs` and `request`, as in `models`; a type with no `request` gets `none`. Dez does not list a model whose types make nothing (`"outputs": []`), and skips a type that is not in `values`, or whose `requiredPath` (a dot path) has no value in the entry. A type can take its `request` from a second value of the entry: `"requestBy": { "path": "...", "values": { ... } }`; a `true` or `false` there has the key `"true"` or `"false"`. A type with `"exclusive": true` wins over the other types of an entry: only the exclusive types count, e.g. for an image model that also tells `"text"` but makes its images only through `mediaApi`. See the built-ins in [`src/model/providers/builtins.ts`](../src/model/providers/builtins.ts). |
| `modelReadableName` | no | Where the server's model list holds a readable name for a model that is named by its id, as `{ "path": "..." }`, e.g. `model_spec.name`. The tooltip of the model shows it after the id. |
| `modelReleased` | no | Where the server's model list holds the release date of a model, as `{ "path": "...", "format": "..." }`: `unixSeconds` for a number of seconds, e.g. `{ "path": "created", "format": "unixSeconds" }`, or `rfc3339` for a text such as `2025-02-19T00:00:00Z` (`created_at` in the Anthropic format). The `model_list` and `model_info` tools show it. |
| `modelTokenPrices` | no | Where the server's model list holds the token prices of a chat model, as `{ "input": "...", "output": "...", "perTokens": 1 }`: dot paths to a number or a text of a number, in USD per `perTokens` tokens (`1000000` for a price per 1M tokens). Optional paths: `cachedInput` (the cached input price), `cacheWrite` (the price of the input that a request puts into the prompt cache; a list of paths gives the first price that the entry has, e.g. `["cache_write_5m", "cache_write"]`), `otherRates` (other rates of some requests), `variableRate` (a second, higher rate of the same tokens, such as the dearest model that a router can pick: with a price there, Dez knows no price for the model), `variableRateBy` (`{ "path": "...", "values": ["..."] }`: a text at `path` that `values` holds also makes the price unknown, for a model whose price is not one number but that has no `variableRate`), `imageOutput` (the price of the image tokens), `audioOutput` (the price of the audio tokens). The `model_list` and `model_info` tools show the price. A tab with a money limit sends a request to a model with no known price only when **Allow unknown prices** of its limit is on. |
| `tokenPrices` | no | The token prices of chat models, for a server whose model list tells none, as a list of rows `{ "match": "...", "input": 3, "output": 15 }`, in USD per 1M tokens. `match` is a regular expression that Dez tests against the model id, with no case; the first row that finds the id gives its price. Optional fields: `cachedInput`, `cacheWrite` (as in `modelTokenPrices`), and `note` (a short text that the price shows, e.g. that a long prompt costs more). A price that the model list tells wins over the table, and a model that no row finds has an unknown price. End each expression after the version, e.g. `^claude-opus-4(-\\d{8})?$`, so that a new model gets no price of an older one. |
| `modelPriceRequest` | no | For a server whose model list tells no price: a free request that tells the price of one chat model, as `{ "url": "https://...", "query": "model", "prices": { ... } }`. Dez sends `GET <url>?<query>=<model id>` with no API key and no `headers`, before a chat request to a model whose price it has not read in the last hour, and when you pick the model. `prices` holds the paths of the price in the JSON of the answer, as `modelTokenPrices` does. Optional: `contextWindow` (`{ "paths": ["..."] }`, the context window of the model in the answer; a model's `"contextWindow"` in `models` wins), and `note` (a short text that each price shows, e.g. that it is a list price). A 404 answer means that the server has no price of the model. Do not use it with `modelTokenPrices` or `tokenPrices`, nor its `contextWindow` with `modelContextWindow`. |
| `modelContextWindow` | no | Where the server's model list holds the context window of a model, in tokens, as `{ "paths": ["..."] }`: one or more dot paths to a number, e.g. `["context_length"]`. With more than one number, the smallest counts. For a model with no number, Dez uses the window of its model family, else 200,000 tokens. The `model_info` tool shows it. |
| `modelImageLimit` | no | Where the server's model list holds the most images of one chat request to a model, as `{ "paths": ["..."] }`: one or more dot paths to a number; with more than one number, the smallest counts. For a model with no number, Dez uses the image limit of its model family, else 20 images. The `model_info` tool shows it. |
| `modelMessageImageLimit` | no | Where the server's model list holds the most images of one message of a chat request to a model, as `{ "paths": ["..."] }`, read as `modelImageLimit` is. A request can then hold more images, in several messages. For a model with no number, a message can hold as many images as a request. |
| `apiKey` | no | When Dez starts, it moves the key into `~/.config/dez/provider_keys.json` and removes it from `app_state.json`. |
| `headers` | no | Extra HTTP headers for every request, as `{ "Name": "value" }`. A name may use only letters, digits, and ``!#$%&'*+-.^_`\|~``. A value must not contain a line break or a control character other than tab. Dez stores headers as plain text in `app_state.json`, so put an API key in `apiKey`, not in a header. |
| `imageRequestHeaders` | no | Extra HTTP headers only for a chat request that sends an image, with the same rules as `headers`. |
| `maxOutputTokens` | no | `max_tokens` for the Anthropic format (default 32000). |
| `cacheBreakpoints` | no | OpenAI format: `true` marks the last two user messages with Anthropic's `cache_control` (the last result of a tool round counts as a user message), for a server that passes the marks on to models that cache only a marked prompt (such as Claude). The Anthropic format always adds the marks. |
| `toolMessageCacheMark` | no | OpenAI format with `cacheBreakpoints`: where a tool result message takes its mark. `part` (default) puts it on the content as one text part; `message` puts it on the message itself. Venice needs `message`. |
| `promptCacheKey` | no | OpenAI format: `true` sends the conversation id as `prompt_cache_key`, so the server can send all the requests of a conversation to the machine that holds its prompt cache. |
| `prefixCacheMark` | no | Anthropic format: `true` adds a third cache mark (`cache_control`) at the end of the fixed start of every request: on the system prompt, which then goes as one text block, or on the last tool when there is no system prompt. A new conversation can then read the tools and the system prompt from the prompt cache that an earlier one wrote. Anthropic allows 4 marks in a request. |
| `requestBody` | no | A JSON object that Dez merges into every chat request, before `settings` and `thinking`: objects merge key by key, and other values replace. E.g. `{ "stream_options": { "include_usage": true } }` for an OpenAI-format server that tells the token counts of a reply only when the request asks for them. |
| `providerSystemPrompt` | no | For a server that adds a system prompt of its own to a chat request, as `{ "bodyPath": "...", "onValue": true, "offValue": false }`. Dez writes `offValue` (default `false`) at the dot path `bodyPath` of every chat request, right after `requestBody`, so the server's prompt is off and Dez's system prompt is the only one. A request of an incognito tab sends no system prompt of Dez, and writes `onValue` (default `true`) there. A value is a text, a number, or `true`/`false`. E.g. Venice: `{ "bodyPath": "venice_parameters.include_venice_system_prompt" }`. |
| `chatClips` | no | OpenAI format: the audio and video clips that a chat request to the server can carry, as `{ "audioFormats": [...], "videoTypes": [...], "maxVideos": 3, "maxBytes": 25000000 }`. Only a `model_invoke` call of a model sends clips, to a text model that reads them (`modelAudioInput`, `modelVideoInput`); a message of the user never does. An audio clip goes as an `input_audio` part, whose `format` is one of `audioFormats` (`wav`, `mp3`, `aiff`, `aac`, `ogg`, `flac`, `m4a`; the list must hold `mp3` or `wav`). A video clip goes as a `video_url` part with a base64 data URL of one of `videoTypes` (`video/mp4`, `video/webm`, `video/quicktime`; the list must hold `video/mp4`). With no `audioFormats` (or `videoTypes`), no clip of that kind goes. Each clip goes as a copy that ffmpeg makes with no metadata: of the same type when the server takes it, else as MP3 (or WAV) or as H.264 MP4. An Ogg clip always goes as MP3 (or WAV): an Ogg file can hold Opus, and `ogg` does not tell whether the server reads Opus. `maxVideos` is the most video clips of one request, and `maxBytes` the most bytes of the copies of all clips of one request together (Dez's own limit is 64 MiB). |
| `imageOutputBody` | no | OpenAI format: a JSON object that Dez merges into a chat request to a model that makes images, after `requestBody` and `providerSystemPrompt`, e.g. `{ "modalities": ["image", "text"] }`. Dez reads the images of the reply from `delta.images`. |
| `audioOutputs` | no | OpenAI format: for chat models that make audio, a list of `{ "modelIdPrefix": "...", "body": { ... }, "contentType": "audio/mpeg" }`. Dez merges `body` into a chat request to a model whose id starts with `modelIdPrefix` (the first entry that matches wins), right after `imageOutputBody`, and reads the audio of the reply, of the type `contentType`, from `delta.audio`. For raw PCM, use e.g. `audio/pcm;rate=24000` and `"pcmSampleBits": 16`. A chat model that no entry names makes no audio in Dez. |
| `mediaApi` | no | The API for the models whose `request` is `image`, `imageEdit`, `upscale`, `tts`, `music`, `video`, `imageToVideo`, `videoToVideo`, `voiceChange`, or `transcription`, as `{ "format": "venice" }`. The formats: `venice` (the Venice image, audio, and video API, at `<baseUrl>/image/...`, `/audio/...`, and `/video/...`), `openrouter` (OpenRouter images, speech, transcription, and video, at `<baseUrl>/images`, `/audio/speech`, `/audio/transcriptions`, and `/videos`; no `upscale`, `music`, `videoToVideo`, or `voiceChange`), and `apimart` (APIMart video, music, transcription, and images: a `video` or `image` request is a task at `<baseUrl>/videos/generations` or `/images/generations`, with its state at `/tasks/<id>`; the input images of a video model that Dez knows, and of an image model whose docs or schema (`image_urls.maxItems`) tell how many images it takes, go first to `/uploads/images?retention_days=3`, one form for each image, and the request sends their web addresses; a `music` request is a task at `/music/generations`, with its state at `/music/tasks/<id>`, and one task can make more than one song; a `transcription` request is a form at `/audio/transcriptions`, with one mp3, m4a, or wav clip of at most 25 MiB (Dez sends a clip of another type as a WAV copy), and its price is unknown, as the answer tells none; the price of the account comes from `/pricing/model`; the rows of a video or image model that Dez does not know come from the request schema of its entry, which the list gives with `"modelListQuery": { "expand": "parameters" }`; only the music models whose fields Dez knows, `suno` and `flowmusic`, take a request). Without it, a request to such a model fails. A `model_invoke` call can ask a transcription for the times of the words: the `venice` format then sends `timestamps=true`, and the `apimart` format sends `response_format=verbose_json` with word and segment times to `whisper-1` (the only model of APIMart that takes it), and Dez writes the times that the answer gives to a file of the work folder of the conversation. The `openrouter` format asks for no times. `"maxRequestsAtOnce"` is the most media requests that Dez sends the provider at one time, of all tabs together (default `4`); the others wait for their turn, in the order of their calls. `"modelRequestBodies"` adds fixed fields to the requests of some models, as `[{ "request": "tts", "modelIdPrefix": "...", "body": { ... } }]`. A form request (`transcription`, `voiceChange`) takes only the top-level text, number, and `true` values, as text fields; `false` and `null` remove the field. `"modelEntryPaths"` (the `openrouter` format) gives dot paths for facts of a media model that the format's own fields do not tell. In each entry of the model list: `speechFormats` (a list of the formats that a speech model makes, such as `mp3`, `wav`, `pcm`: the choices of a Format row, with `mp3` as the default when it is there, else `wav`), `speechSpeed` (the speeds of a speech model, as `{ "min": 0.7, "max": 1.5, "default": 1 }`: a Speed row when `min` is less than `max`), `speechMaxCharacters` (the most characters of the text of a speech request), `speechCharacterPrice` (the price in USD of each character of the text of a speech request), `transcriptionFormats` (a list of the file formats that a transcription model takes, such as `mp3`, `wav`; when the list has `wav`, Dez sends a clip of another type as a WAV copy), `transcriptionMaxBytes` (the largest file that a transcription model takes, in bytes), `transcriptionMaxSeconds` (the longest clip that a transcription model takes, in seconds), `transcriptionMinutePrice` (the price in USD of each minute of the clip of a transcription), and `requestPrice` (the price in USD of one speech or transcription request, whatever the length of its text or clip). A price at one of these three paths wins over the token prices of the entry's `pricing`; a price can be a number or a text of a number. In each entry of the video list (`<baseUrl>/videos/models`): `videoAudioMode` (the text `configurable`, `always`, or `none`: only `configurable` gives an Audio switch, on by default), `videoRoutePrices` (the prices of the model as an object with one entry for each route, each `{ "unit": "job", "examples": [...] }` as in TrustedRouter's `pricing.routes`; with this path, Dez reads no other video price), and `videoRoute` (the name of the route that a request takes; without it, or when the prices do not have that route, only prices of one route give a price). |
| `settings` | no | On/off toggles for the provider settings popup in the model picker. Each toggle writes a value into the chat request. See the Venice `settings` in [`src/model/providers/builtins.ts`](../src/model/providers/builtins.ts). The keys `thinking` and `tools` are reserved for the Thinking and Tools toggles. A toggle shows, and writes its value, only for the models that take it: `"modelIdPrefix"` gives the start of their ids, and `"modelSupport"` (read as `modelToolCalling` is) gives where the server's model list tells it; a list there means "takes it" when it holds the first name of the toggle's `bodyPath`. |
| `thinking` | no | Set it when the server's models think. See [Thinking](#thinking). Checking **Supports thinking** writes `{}`; unchecking it removes the field. |

The base URL rule:

- **OpenAI format**: the base URL includes the version, the same as in the OpenAI SDKs. Dez sends chats to `<baseUrl>/chat/completions` and gets models from `<baseUrl>/models`. Common local base URLs are `http://localhost:8080/v1` (llama-server), `http://localhost:1234/v1` (LM Studio), `http://localhost:11434/v1` (Ollama), and `http://localhost:8000/v1` (vLLM).
- **Anthropic format**: the base URL has no `/v1`, the same as in the Anthropic SDKs, e.g. `https://api.anthropic.com`. Dez sends chats to `<baseUrl>/v1/messages` and gets models from `<baseUrl>/v1/models`. If the base URL ends in `/v1`, Dez removes it.

Dez drops an entry that is not valid, and the other providers still load. The next time Dez saves `app_state.json`, the dropped entry is no longer in the file, so keep a copy of your edits until they work.

A provider shows in the model picker only while its last model check worked. If a local server was off when Dez started, start the server, then click **Check again** in Settings › Providers. The model picker also checks again when you open it, at most once a minute per provider.

## Thinking

A custom provider that has `thinking` gets the Thinking toggle (on by default) in Settings › Providers and in the model picker's settings popup. While the toggle is on, Dez shows the thinking that the server streams, and sends the thinking of earlier responses of the same model back to the server.

Dez reads thinking from these parts of a reply:

- **OpenAI format**: the `reasoning_content`, `reasoning`, `reasoning_text`, or `reasoning_details` field of a delta, or a reply that starts with `<think>` or `<thought>`.
- **Anthropic format**: `thinking` and `redacted_thinking` blocks.

`thinking` is an object with two optional fields. Each one is a JSON object that Dez merges into the chat request: objects merge key by key, and other values replace. `enabledBody: {}` sends nothing.

| Field | Sent when | Default |
|---|---|---|
| `enabledBody` | the Thinking toggle is on | OpenAI format: nothing. Anthropic format: `{ "thinking": { "type": "adaptive", "display": "summarized" } }`. |
| `disabledBody` | the Thinking toggle is off | nothing |

Some servers reject a field for thinking that their model does not support. For example, Claude Sonnet 4.5, Opus 4.5, and Haiku 4.5 reject `adaptive`. For those, set `enabledBody` by hand, e.g. `{ "thinking": { "type": "enabled", "budget_tokens": 8000 } }`, or uncheck **Supports thinking**.
